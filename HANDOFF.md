# Berto Lucci — working on this project from another computer

**Live:** https://berto-lucci.vercel.app
**Vercel project:** `berto-lucci` (team `webactionhellascom`, account `webactionhellas-dev`)

---

## Read this first

**Vercel does not store your source code.** It stores a *built* copy of the site.
`vercel pull` fetches environment variables and project settings, not the project.
There is no way to open this project on a new machine "from Vercel" alone.

To work from anywhere you need the source in **Git**. That takes one setup step,
below, after which the workflow is: edit anywhere → `git push` → Vercel rebuilds
and deploys automatically.

Until you do that, the only way to move the project is copying the source zip.

---

## Step 1 — put the repo on GitHub (do this once, on this PC)

The repository is already initialised and committed here, images excluded,
**10.9 MB total**. You just need a remote.

1. Create an **empty private** repo at <https://github.com/new> named
   `berto-lucci`. Do not add a README, .gitignore or licence.
2. Then run, from `C:\Users\USER\Downloads\berto-lucci-optimized\berto-lucci-final`:

```bash
git remote add origin https://github.com/<your-username>/berto-lucci.git
git branch -M main
git push -u origin main
```

Git will ask you to sign in to GitHub in the browser the first time.

## Step 2 — connect Vercel to that repo (once)

1. Open <https://vercel.com/webactionhellascom/berto-lucci/settings/git>
2. **Connect Git Repository** → pick `berto-lucci`.

From then on every push to `main` deploys automatically, and pull requests get
their own preview URLs.

---

## Step 3 — on the other computer

```bash
git clone https://github.com/<your-username>/berto-lucci.git
cd berto-lucci
npm install
npm run dev
```

That is the whole setup. **Product photography loads from Shopify's CDN
automatically**, so you do not need to copy the 1.8 GB image library. The site
looks and behaves identically.

Requirements: **Node 18.18+** (Node 24 is what this was built on) and npm.

## Everyday commands

| What | Command |
|---|---|
| Dev server (hot reload) | `npm run dev` |
| Production build | `npm run build` |
| Serve the production build | `npm run start` |
| Type check | `npx tsc --noEmit` |
| Deploy to production manually | `npx vercel deploy --prod --yes --scope webactionhellascom` |
| Re-link a fresh clone to Vercel | `npx vercel link --yes --project berto-lucci --scope webactionhellascom` |

Once Git is connected (Step 2) you rarely need the manual deploy: pushing is enough.

## Environment variables

Only one, and it is already committed in `vercel.json`, so **nothing to configure**:

| Variable | Value | Meaning |
|---|---|---|
| `NEXT_PUBLIC_IMG_CDN` | `1` (default) | Serve product images from Shopify's CDN |
| | `0` | Use the local `public/bertolucci_images` library instead |

Set `0` **only** on a machine that actually has the image folder. On a fresh
clone, leave it alone.

## What is deliberately NOT in the repo

| Excluded | Why | Need it back? |
|---|---|---|
| `public/bertolucci_images` (1.8 GB, 15,912 files) | Production serves these from Shopify's CDN, which holds the **originals at 1550×2325** — higher resolution than these local 1200px copies. Committing them would make the repo unusable. | Only for offline work. Copy the folder manually and set `NEXT_PUBLIC_IMG_CDN=0`. |
| `node_modules`, `.next` | Regenerated by `npm install` / `npm run build`. | Never. |
| `.vercel` | Machine-local project link. | Run `vercel link` (see table above). |
| `*.zip` | Local snapshots. | No. |

To regenerate the WebP/AVIF twins if you ever restore the image library:
`node scripts/build-image-formats.mjs`

## Known open items (not bugs I left behind — decisions waiting on you)

1. **The three TikTok videos are missing.** `public/videos/` has no media, so each
   reel shows a "watch on TikTok" link instead of playing. Drop `reel-1.mp4`,
   `reel-2.mp4`, `reel-3.mp4` in there (see `public/videos/README.md`). This is
   the only reason that section is not finished.
2. **Checkout is a demo.** It cannot take payment; it explains itself and clears
   the bag. Wiring real Shopify checkout is the backend phase.
3. **Two different Instagram handles** are used in the code
   (`bertoluccimilano` in the social section, `bertolucci_milano` in the footer
   and structured data). One is probably dead. Pick one.
4. **Legal pages need a Greek lawyer.** The copy is live in both languages, but
   it cites **Law 2472/1997, which has been repealed**, the homepage badge says
   "30-Day Returns" while the policy grants **14 days**, and the statutory
   two-year guarantee, model withdrawal form and ADR body are all missing.
5. **Only one language can be indexed by Google.** Language is chosen by a cookie
   at a single URL, so search engines only ever see English. Fixing it properly
   means `/el` and `/en` routes with hreflang, which changes every URL.

## Project shape, briefly

- **Next.js 15.5 / React 19 / Tailwind 3 / Radix**, App Router, TypeScript.
- **483 products** from `public/data/bertolucci_products.json`; the shop grid uses
  the slim `public/data/shop-list.json` (regenerated automatically on `prebuild`).
- **Bilingual EN/EL** — `lib/i18n.ts` (UI) and `lib/legal.ts` (legal pages). The
  Greek deck is typed against the English one, so a missing translation is a
  **compile error**, not a silent gap.
- **Greek typography matters here:** the brand fonts (Bodoni Moda, Jost,
  Cormorant Garamond) contain **no Greek glyphs**. Greek is rendered by paired
  companions (GFS Didot, EB Garamond, Noto Sans) via per-glyph fallback in
  `tailwind.config.ts`. If you add a font, check it actually has a `greek`
  subset, or Greek text will silently fall back and break its own layout.
